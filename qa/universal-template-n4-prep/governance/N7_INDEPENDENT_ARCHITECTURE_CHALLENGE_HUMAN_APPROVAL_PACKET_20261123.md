## Part B — N7 minimum contract clarifications for future TEST-only implementation
1. **Authoritative persistence:** choose a durable transactional store for idempotency and publish-intent (not Google Sheet), unique key and per-lesson serialized state; distinguish external projected rows from atomic manifest pointer. Pending retries converge through reconciliation.
2. **Canonical intent digest:** versioned canonical serialization; hash binds requestId, idempotencyKey, lessonId, source SHA and revision, candidate SHA, target Sheet ID, exact rows/actions, grant epoch and actor service. Approval is over digest + approved operation scope, not a free-text status.
3. **Writer lifecycle:** `RECEIVED -> AUTHORIZED -> RESERVED -> PROJECTION_PENDING -> VERIFIED -> COMMITTED`, with explicit `RECONCILE_REQUIRED`, `REJECTED` terminal outcomes. Never write `ACTIVE` in N7; recovery of a failed projection cannot grant release.
4. **Gate predicate:** valid N0-S signed receipt AND N5 all five independently signed CLOSED AND DB-01 pass AND Owner-issued TEST-only, time-scoped, revoked-checked grant AND independent QA N7 security architecture signoff AND live input freshness; default false.
5. **Environment isolation:** allowlist only exact TEST spreadsheet `1HlHOrvAQCt4HzOPlaX0moLdRP69ITnPLtEjy6mt_6zs`; tabs 10/11 immutable by writer, tabs 12–16 metadata projections only after future explicit grant; source original Sheet ID `1ZFzjU1HbAOp0ZH4GNmBxMXci8YzLtPQHQixCX9ZITT8` must never be writer target. No GAS, main, real student records, private keys, public answers or manifest ACTIVE.
6. **No secrets in docs/CI:** separate deploy-time secret manager, key rotation, audit trail and least privilege; hardcoded N6 test HMAC is deliberately never a real approval verifier.
7. **Test additions before any grant:** `N7-T01` same idempotency key, different payload/target/digest; `N7-T02` two concurrent first writers + process restart; `N7-T03` inject failure between each Sheet/journal/outbox phase and replay; `N7-T04` manual external Sheet edit during transaction; `N7-T05` approval digest replay/nonce/role separation/revocation/expiry; `N7-T06` forbidden tab/Sheet mutations; `N7-T07` stale receipt/manifest CAS; `N7-T08` rollback failure/readback. These are **specified, NOT executed**.
8. **Reconsider design choice:** if durable transactional store, independently authenticated approval verifier or restricted service principal cannot be provided, remain on READ-ONLY / LOCAL DRY-RUN. Do not substitute Sheet `LockService` as universally cross-writer-atomic or declare Google Sheets a transaction store.
