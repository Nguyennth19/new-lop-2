## Approved scope and rationale
Owner previously accepted QA-D on Windows Chrome 157 (13/13 manual checks) and observed that A=8 L and B=5 L were displayed with equal-size silhouettes and without 1 L graduations. This is a **visual pedagogy enhancement**, not an engine calculation defect. Preserve V1.1 as immutable rollback.

The new V1.2 renders two vessels with equal cross section, same bottom datum, identical pixel height per liter in a single exercise and *vessel height proportional to each capacity*. Each capacity of 1–100 L remains accepted by original engine; per-liter step is `Math.min(19,158/maxCapacity)` SVG-viewBox units and can shrink for large values. Every liter has a tick; for capacities over 12 L, text labels are thinned to avoid overlap, without dropping unit ticks. The fill level is `currentLiters × commonUnitStep` from the shared baseline. At 8 L vs 5 L: capacity heights 152 vs 95 SVG units; water 3 L vs 1 L: 57 vs 19 units. Three liters in both vessels are at the same elevation from the shared baseline under the explicit equal-area model.

### Deliberate design choice
This is an abstract mathematically scaled rectangular vessel with **constant cross section**. Real bottles with rounded necks or different geometry cannot be treated as equal linear volume vs height, so no source PNG/WebP is used to represent the dynamic quantity. Static `KL_M05_009` remains a non-bound illustrative candidate.
